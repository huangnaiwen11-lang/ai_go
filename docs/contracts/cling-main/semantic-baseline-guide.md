# Cling 主站业务语义基线使用说明

`semantic-cases.json` 是 Go 主站重构的前置门禁，不是接口文档或测试数据的替代品。它固定客户端可观察的 HTTP 结果、主站自有数据库前后事实、账本变化、任务状态和外部调用摘要；任何重构实现都不得只比对响应而忽略预扣、冲正和幂等事实。

## 使用规则

1. 新增或修改用户可感知行为前，先新增或更新一个案例，再编写对应的 Go 单元测试与集成测试。
2. 运行 `go run ./cmd/semantic-contract-check --cases docs/contracts/cling-main/semantic-cases.json`。校验器会拒绝缺少状态事实、模板上下文、技术调用摘要或包含敏感字段的案例。
3. 案例中的数据均为合成摘要。不得写入真实用户、会话、令牌、签名、支付凭证、素材 URL 或提示词。
4. `source.kind` 只能是 `confirmed_business_baseline` 或 `isolated_local_node_observation`。两者冲突时，以前者为准，并在相应的设计或迁移说明中记录差异原因。
5. `technical_calls` 只允许三个中台原子：`text_to_image`、`image_edit`、`image_to_video`。空数组表示本案例不向中台提交请求；它不能省略。

## 已冻结的硬约束

- 游客生成必须返回 403 `ACCOUNT_BINDING_REQUIRED`；VIP 门禁必须返回 403 `VIP_REQUIRED`；余额不足必须返回 402 `INSUFFICIENT_FUNDS`。
- 生成顺序为：业务门禁 → 主站任务占位 → 原子预扣 → 中台提交。不能先查余额再创建任务。
- 提交失败、技术失败和取消都只冲正一次；审核没收不退款，也不恢复已消耗的每日免费额度。
- 文生视频是父任务加 `text_to_image` 首帧步骤和 `image_to_video` 步骤，用户只结算一次。
- 生成中台调用只带技术执行、主站任务、协议、幂等键和主站回调事实；不带钻石、余额、VIP、每日额度、支付或账本事实。
- PayCores 与商店内购只提供支付事实；主站经校验后在自己的账本入账，同一外部交易只能入账一次。

## 当前边界

这些案例是本地 Go 骨架和后续集成测试的业务裁决基线，不授权部署、生产访问、流量切换，或改写 Node/JS、PayCores、生成中台的业务路径。当前案例使用前端已使用的兼容入口作为消费者路径；实际 API 平移时必须在兼容清单中逐条核对请求与响应字段，不能据此擅自扩展路由范围。
