# Go 本地支付订单冻结设计

## 目标

在 Go 自有 MongoDB 中维护可发布的钻石商品和支付订单。订单创建时冻结用户、渠道、商品版本和钻石数；已验证的 PayCores 回调只能按本地订单结算，绝不采信回调中的钻石数，也不读取 Node 钱包或订单。

## 边界

- 本阶段仅支持一次性钻石商品；VIP 订阅、游戏订单和 HTTP 回调路由保持 Node 现有语义。
- 商品只从 Go 自有 `payment_products` 读取。未发布、未知或版本不一致的商品不能创建订单。
- 支付订单保存 `user_id`、`provider`、`provider_order_id`、`product_id`、`product_version`、`diamond_amount`、状态和时间。
- 收到已验证的渠道信号后，服务按订单冻结事实创建 `Receipt`，复用已有本地回执入账；回执、订单状态、账户余额和 `payment_credit` 分录在一个 Mongo 事务中提交。
- 产品价格或钻石数变更通过新增商品版本发布；旧订单继续按原快照结算。

## 数据流

```text
已发布 Go 商品 → 创建本地支付订单并冻结商品快照
已验证 PayCores 信号 → 查找本地订单 → 构造冻结 Receipt
                      → 同事务入账 + 订单完成
```

## 不在范围内

- 不调用 PayCores 创建收银台订单。
- 不注册或切换 Go 支付回调路由。
- 不保存回调原始签名、请求体或密钥。
- 不迁移 Node 历史订单、钱包、VIP 或游戏支付。

## 验收

- 商品变更后，旧订单仍按创建时冻结的钻石数结算。
- 已验证交易号只能结算一次；订单或用户不一致时拒绝。
- 任一入账或订单状态写入失败，回执、余额、账本和订单状态全部回滚。
- 未发布商品、错误渠道订单和未知订单无法结算。
