# 2026-09-14 本地 Go 独立处理验证

## 范围与隔离

本轮执行现有代码的完整测试，并修复验收过程中暴露的测试清单漂移和前端编译错误。
没有启动或修改旧 Node 后端，没有连接生产、真实 OAuth、PayCores、商店或生成中台。

- 使用本机已有的 `mongo:8.0` 镜像创建临时 `rs0`，数据目录使用 tmpfs。
- Go 测试运行在共享该临时 MongoDB 网络的独立容器中，源码只读挂载。
- 测试连接为容器内的 `127.0.0.1:27017`，不是宿主机上已有的 Go 或 Node 数据库。
- 不放宽现有 MongoDB 主机、端口、数据库名和副本集校验。
- 外部 HTTP 依赖由测试自身的本地桩提供，不使用真实供应商。

## 修复内容

1. 数据库集成测试的固定集合清单遗漏 `feedbacks`、`notifications`，索引清单遗漏通知索引。
   补齐为 22 个集合、29 个索引，保留实际 MongoDB 集合与索引字段检查。
2. 新增 `TestFrozenSchemaCoversAllDeclarations`，在没有数据库时也检查固定清单与 schema
   声明的双向覆盖及重复项。修复前该测试明确报告上述三项遗漏，修复后通过。
3. 三个 Gateway 账号和支付闭环测试的 Node 上游改为失败探针：任何请求回退都会调用
   `t.Errorf` 并返回 502。它不提供 Node 业务实现。
4. 前端 SSE 的 `JSON.parse` 输入改为明确的字符串，解析结果仍为 `unknown`。
   保留非 JSON 原文语义并增加对应回归测试。
5. 统一验收脚本加入离线 schema 清单检查，并分别检查前端 `tsconfig.app.json` 和
   `tsconfig.node.json`。原来的根配置仅有 references，`tsc --noEmit` 没有检查应用源码。

## 能证明什么

- 已执行的账号、支付 Gateway 用例没有请求 Node 回退探针。
- 现有 MongoDB 仓储及生成传输层用例覆盖的预扣、回调、失败冲正、审核没收、文生视频
  两步编排等流程可以在隔离 Go 数据库上运行。
- 本轮解决了两个此前会被有限门禁遗漏的问题：数据库验收清单漂移和前端正式构建失败。

## 仍不能证明什么

- 尚未完成从浏览器逐页操作到 Go 的全量端到端验收，不能据此声明整个前端已脱离 Node。
- Gateway 默认代理策略未改变，测试通过不自动修改路由放行矩阵。
- OAuth、商店真实验证器和 Redis 适配等代码缺口仍在；真实供应商验收、生产灰度也未完成。
- 管理后台和 Animate 不在本次迁移范围内。

下一步应补浏览器端到端验收和未完成的实际适配代码，而不是只重复运行静态门禁。
