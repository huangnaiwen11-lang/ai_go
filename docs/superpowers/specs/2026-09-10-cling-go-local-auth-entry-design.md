# Cling Go 本地账号入口一期设计

## 目标

在独立本地 MongoDB 的 Go Gateway 中，实现邮箱密码注册、邮箱密码登录、移动端游客登录和当前用户读取。新能力使用 Go 自有用户、凭据、会话与账户数据，不读取或写入 Node 用户、JWT、钱包和生产配置。

本期的目标是平移已确认的用户可见语义，而不是将现网全部身份提供商一次迁移到 Go。

## 范围与红线

本期仅在显式开关开启后接管以下精确无查询路由：

| 路径 | 方法 | 本期行为 |
| --- | --- | --- |
| `/api/auth/register` | `POST` | 邮箱密码注册并签发 Go 自有会话。 |
| `/api/auth/login` | `POST` | 邮箱密码登录并签发 Go 自有会话。 |
| `/api/auth/guest` | `POST` | 仅 iOS、Android 的设备游客登录。 |
| `/api/auth/me` | `GET` | 读取当前 Go 用户的安全投影。 |

下列请求一律继续透明代理 Node：OAuth、Google 游客升级、Apple、Facebook、Twitter、魔法链接、推送令牌、退出登录，以及任意不满足精确候选规则的请求。

不得新增客户端可直接提交 `provider + subject` 的游客绑定接口。现网游客升级依赖 Google 身份令牌验签；绕开该验签会造成账户劫持风险。已有 `identity.BindGuest` 领域用例继续保留，待独立测试环境具备 Google 身份验签后，通过现有升级路径接管。

## 语义基线

- 邮箱必须规范化并校验格式；密码最少 6 个字符。
- 对正常或封禁账号，已注册邮箱返回冲突；已删除账号不再占用邮箱，新注册会创建新的 Go 用户与新凭据。错误密码和不存在邮箱均返回相同的未认证错误，避免泄露账户是否存在。
- Web 游客登录返回 `403 WEB_GUEST_LOGIN_DISABLED`；仅 iOS、Android 可创建或复用设备游客。
- 相同 `deviceId` 与平台重复游客登录必须返回同一用户；不得创建第二个账户。
- 注册不发放注册奖励，初始钻石余额为 0；用户仍可通过后续支付为 Go 自有账户充值。
- 用户时区仅在首次创建时固化，重复登录和后续绑定不得覆盖。
- 账号封禁或删除后，所有既有 Go 会话立即失效。

## 模块与数据职责

`internal/biz/identity` 继续拥有用户、会话、游客状态与绑定规则，并新增注册、密码登录、游客登录与当前用户读取用例。密码明文绝不进入领域对象、日志或响应。

`internal/biz/authcredential` 作为独立领域模块拥有密码凭据的 Argon2id 编码、校验与重哈希策略，以及凭据仓储接口。它只返回“校验通过 / 不通过”，不向 transport 或其他业务模块暴露哈希内容。

`internal/data` 增加 `credentials` 集合。凭据文档保存 `email_normalized`、所属用户、由领域模块生成的 Argon2id 编码哈希与 `active` 状态；通过仅覆盖 `active=true` 的唯一索引保证正常和封禁用户邮箱唯一。用户删除时在同一事务中停用其凭据，因此删除账号的邮箱可重新注册。该层只负责凭据持久化和条件创建。用户、会话、账户仍复用已有集合及其各自仓储。

`internal/transport/authentry` 只处理严格 JSON、认证头、HTTP 响应信封与错误映射。它不能访问 MongoDB，不能计算密码哈希，也不能跨模块读取账本。

`cmd/api-gateway` 仅在 `GATEWAY_GO_SESSION_AUTH_ENABLED=true` 与新的账号入口显式开关都开启时装配本地 Handler。开关关闭、文件缺失、路径不精确或请求含 OAuth 字段时，Gateway 必须继续代理 Node。

## 凭据与会话

密码使用 Argon2id 派生哈希，哈希中保存版本、盐和参数。参数由 Go 配置提供，配置只允许安全下限，升级参数时在下次成功密码登录后安全重哈希。比较必须使用常量时间比较。

会话使用随机、不透明的 256 bit 标识，服务端仅保存会话事实；Bearer Token 的有效期为 30 天，与现网默认登录 Token 时长一致。响应或日志不得包含密码哈希、盐、会话内部版本或身份绑定技术细节。

## HTTP 合同

成功响应沿用根层信封：`{"success":true,"data":{...}}`。注册成功返回 `201`，登录、游客登录和当前用户读取返回 `200`。

公开用户投影仅包含稳定业务字段：用户 ID、显示名、绑定状态、账号状态、内容访问级别、首次时区和游客标记。密码、会话版本、凭据、余额、外部身份 subject 均不返回。

错误码保持可区分：输入非法为 `400 INVALID_REQUEST`，邮箱已注册为 `409 EMAIL_ALREADY_REGISTERED`，错误邮箱或密码为 `401 INVALID_CREDENTIALS`，Web 游客禁用为 `403 WEB_GUEST_LOGIN_DISABLED`，封禁或删除会话为 `401 UNAUTHENTICATED`，依赖异常为 `503 SERVICE_UNAVAILABLE`。

## 创建与登录流程

注册在单个 MongoDB 事务内完成：规范化邮箱 → 条件创建用户 → 创建 Argon2id 凭据 → 创建余额为 0 的账户 → 创建会话。任一步失败整体回滚。并发注册相同邮箱时仅一个事务成功，另一个返回邮箱冲突；已删除用户的非活动旧凭据不参与唯一性判断。

密码登录读取凭据并执行安全比较；验证成功后检查用户账号状态，创建新的 30 天会话。错误邮箱和密码采用等价的比较路径与相同错误响应。

移动端游客登录以平台和设备标识为唯一业务键。不存在时在事务内创建 `guest` 用户、零余额账户和会话；已存在时校验账号状态后创建新会话。Web 请求在任何写入前拒绝。

## 测试与验收

先用 TDD 覆盖领域、MongoDB 事务、HTTP Handler 和 Gateway 分流：

1. 邮箱规范化、重复注册、弱密码、错误密码与账户枚举防护。
2. Argon2id 参数下限、重哈希、密码不泄露与凭据唯一索引。
3. iOS/Android 游客创建及复用、Web 游客拒绝、时区只写一次。
4. 封禁或删除后旧会话立即失效。
5. `register → login → me` 与 `guest → me` 本机 rs0 端到端闭环。
6. 开关关闭、OAuth 字段、query、编码路径和未列路由必须透明代理 Node。

所有集成测试只能连接 `127.0.0.1` 上 `cling_main/rs0`，并且仅按随机精确 ID 清理测试数据。完成后必须运行 `go test ./...`、`go test -race ./...`、`go vet ./...`、Gateway 构建和语义契约检查。

## 非目标与后续

本期不接真实 OAuth、邮件、魔法链接、Google 游客升级、真实 PayCores、商店内购或真实生成中台。下一阶段在独立测试环境配置身份提供商、支付渠道和生成中台回调后，分别做真实外部依赖金丝雀，不直接切换生产用户流量。
